## The release flow (never skip)
1. Edit the source, then run `python3 home-page/src/build.py`.
2. Extract the last `<script>` of `home-block.html` and run `node --check` on it.
3. Run the tests listed in `src/README.md`. `hm.js` must end with `1300 hscroll 0 []` and `390 hscroll 0 []`.
4. Take screenshots and **look at them** yourself at 390, 768, 1300 and 1440 wide.
5. Commit and push to `main`. Write the commit id into `VERSION-DEV`, then commit and push again. Check it with
   `git show origin/main:home-page/VERSION-DEV`. raw.githubusercontent can take about 5 minutes to update.
6. **Publish to /home-dev only.** Write to `VERSION`, which moves /home-test (the page testers use), only when
   Nirvan says "move it to home-test".
7. Send Nirvan a screenshot of each change, plus one line on any design call you made for him.

Do the commits and pushes yourself. Don't hand Nirvan git steps.

## Design system
**Palette: use only what the site already has.** These come from `build.py`:
- Purple `#6152a0` (primary: buttons, links, the active pill). Ink `#1b1526` (headings and body text).
- Slate `#5b6478` and `#6b6478` (secondary text). Dark plum `#3a3245`.
- Lavenders: `#f6f3fc`, `#ece7f7`, `#ebe7f5`, `#d9d3ec`, `#d9d1ee`, `#cfc8e6`. Use them for backgrounds,
  borders and level headers.
- The header has a very light sky-blue tint. Supporting blues: `#33697f`, `#3b6fb3`.
- **Never use** gold or yellow buttons, teal accents, black or dark header bars, boxed pill badges, or a
  rainbow of colours. Nirvan calls these "tacky" and "hoky". The only exception is the rainbow level colours
  in the pending badge mockup, which waits on his answer (see STATUS.md).
- Mood: **subtle, clean, spacious, cinematic.** When in doubt, take colour away rather than adding it.
  Use a slightly darker lavender for emphasis, not a bold colour.
- The look should echo the hero image (Rick in his suit in the desert) and whatatrip.com/donors.

**Type and layout**
- Display fonts: `WathCinzelDeco` and `WathRye`, used only for titles. Body text inherits the site font.
- Use the site's existing button, heading and text-size styles. Don't invent new ones.
- Use a consistent spacing scale (4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 px). Give sections breathing room,
  with dividers or film photos between dense blocks of text.
- Level list: square edges, light purple. Each level is its own outlined box with a small gap between boxes.
  Each has a slightly darker lavender header ("$25K+ LEVEL NAME"), limited perks as quiet purple
  "38 of 50 left" text, a **Give** and a **Details** button, and the text link "or start a fundraiser and raise this".
- Phone layout: follow Kickstarter's mobile patterns.

**Zero overlapping or clipped text, anywhere.** After every layout change, check the *whole* page and the
member and staff screens, not just the spot that changed, at 360, 390, 768, 1300 and 1440 wide. There must be
no horizontal scroll. Check long names, long numbers, and the logged-in and logged-out states.

## Front-end best practices
- **CSS:** add new rules before the last `:is(#wath,#wath-top) .upx{display:flex;` in `build.py` (see README).
  Scope every selector: `:is(#wath,#wath-top)` for the page, `#wath-top` for the member and staff overlay,
  `#header` for the Squarespace header. Later rules win, and the file already has many overrides,
  so **search for an existing rule and change it rather than stacking another override.**
  Prefer flexbox or grid with `gap`, `min-width:0` on flex children, and `clamp()` for type that changes with
  screen width. Avoid fixed heights on anything that holds text.
- **Accessibility (WCAG 2.1 AA):** text contrast of at least 4.5:1 (3:1 for large text), visible focus rings,
  everything usable by keyboard, tap targets of at least 44×44 px, real `<button>` and `<a>` elements,
  `alt` text on images, form labels, `aria-expanded` on drop-downs and chevrons, Esc closes pop-ups and focus
  returns to where it was, and `prefers-reduced-motion` respected.
- **Performance:** keep the page fast. Size and compress images (WebP, with `srcset` for 1x and 2x),
  `loading="lazy"` below the fold, explicit width and height (or aspect-ratio) so nothing jumps, no new heavy
  libraries, and load fonts with `font-display:swap`. Serve assets from jsDelivr pinned to a commit, as the page already does.
- **JavaScript:** small, focused changes. When replacing a function, match its own closing brace (a past
  slice once deleted a whole data array). Run `node --check` after every edit. Never append `// comment`
  after a `},` (it swallows the comma). Some characters (`→`, `—`) are literal UTF-8 in the file, so grep
  before matching on them.
- **SEO and privacy before launch:** every development page (/home-dev, /home-test) stays `noindex` and out of
  search until Nirvan says the site is launching. Add no analytics or pixels unless he asks.
  (Google Analytics is approved; no Meta pixel.)

## Database and security (Supabase)
- **Ask Nirvan in chat before applying any migration,** and say in plain words what it changes.
  Make changes as named migrations, never as untracked edits.
- Row Level Security on every table. Members can read and write only their own rows. Staff powers go through
  `security definer` functions that check the caller's role and set `search_path`.
  Run the Supabase security and performance advisors after schema changes and fix what they flag.
- Only the **publishable** key ever goes in `app.js`. Secret keys, the Resend API key and the Pledge API key
  belong only in Supabase function secrets.
- Roles: Owner (Nirvan), Admin (Nirvan, later Dream), Manager (helper plus editor), Editor (content only, with no
  access to people's profiles). Donor and Supporter are worked out automatically from gifts.
  Only the Owner or an Admin may delete a member. Deleting takes two steps (type DELETE) and keeps gift records.
- Privacy: email, phone and mailing address are **private**. Label them that way and never show them publicly.
  The minimum age for an account is 13. Passwords must be at least 10 characters, with required character types
  and leaked-password protection. Profile changes apply at once, with no staff approval step.

## Donor numbers: get them right
- Any total the page shows must be **computed from the rows under it.** Never hard-code it.
  (Rachel Hamilton's challenge once showed $64,750 when its rows added up to $63,750.)
- Pledge API facts: "processed" means real gifts, "pledged" means match credits, "draft" means unfinished,
  "blocked" means a stopped payment. API amounts include the donor's tip; `donation_amount` is the gift alone.
- When testing, feed in the live data by routing `**/donors.json*` and `**/macros/**`. Rendering the seed alone proves nothing.
  Also run the "before" case to confirm a test really catches the bug.
- Donor names are set in `name-fixes.csv`. "Sarena Snider" is correct as spelled.
